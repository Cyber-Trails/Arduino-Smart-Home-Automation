# Troubleshooting and Learning Evidence

**Project:** CEIS101 IoT Smart Home Automation  
**Author:** Mildred Owens  
**Source:** Original 29-page academic presentation, especially pages 27–28.

## Challenges documented by the student

### Component identification
**Challenge:** Many unfamiliar electronic parts needed to be distinguished and connected.

**Response:** Labeled individual component packets and studied their functions and basic electronics before integrating them into the prototype.

**Transferable practice:** Component inventory, technical research and preparation.

### Two blue LEDs did not illuminate
**Challenge:** Two blue LEDs failed while the expected code had been loaded.

**Response:** Learned to use an electrical tester; testing identified the LEDs as faulty.

**Transferable practice:** Isolating a hardware problem rather than assuming every failure originates in software.

### USB cable length restricted access
**Challenge:** The available USB 2.0 Type B cable was too short for convenient circuit work.

**Response:** Used a longer cable to improve access and movement around the system.

**Transferable practice:** Adjusting the physical test setup for reliable hands-on iteration.

### Photoresistor did not respond correctly
**Challenge:** The initial photoresistor failed to produce the expected behavior.

**Response:** Checked wiring, code and upload behavior before replacing the sensor. The replacement photoresistor worked.

**Transferable practice:** Checking multiple potential causes and retesting after hardware replacement.

### Jumper wires were too short
**Challenge:** Short wires complicated component placement and made connections difficult to follow.

**Response:** Rearranged breadboard component placement to make connections neater, less tangled and easier to trace.

**Transferable practice:** Physical layout design, troubleshooting accessibility and maintainability.

## What the evidence does and does not establish

The presentation documents working demonstrations and the author's reported troubleshooting, but it does not establish a security assessment, independently repeated laboratory measurements, production deployment or an active cloud connection. These details are recorded as the student's historical academic work.

**Career relevance:** Hardware diagnostics, technical observation, systematic troubleshooting, introductory embedded-systems integration, testing, data interpretation and documentation.
